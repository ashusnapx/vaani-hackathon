# Vaani Feature Reference

Source: mirrored docs in [`vaani/`](vaani/INDEX.md) (run `docs/vaani/sync.sh` after cloning) plus the site's [pricing](https://www.vaani.dev/pricing), [developers](https://www.vaani.dev/developers) and [platform](https://www.vaani.dev/platform) pages, dated 2026-10-31. Where two docs disagree, the note marked **Conflict** says which one to follow.

## Essentials

- **Base URL:** `https://api.vaanivoice.ai`. Every path starts with `/api/`. API version 2.0.0. **Auth:** header `X-API-Key: vaani_<key>`. The header name is case-sensitive, and `Authorization` does not work. One key covers the whole workspace, and it is shown only once. See the [intro](vaani/introduction.md) and [API key](vaani/getting-started/generate-api-key.md) pages.
- **IDs:** find `agent_id` (UUID) at [platform.vaani.dev](https://platform.vaani.dev) → Agent Config → agent → Overview. Create API keys at Settings → API Keys (site/developers.md says Developers → API Keys). For this repo, the key is in repo-root `.env` as `VAANI_API_KEY` (gitignored). `call_id` looks like `outbound-1776774443-863aa698` (older pages show `room-f5237622`). See the [identifier table](vaani/getting-started/overview.md#important-identifiers), [account setup](vaani/getting-started/create-account.md) and [the four ways to create an agent](vaani/getting-started/create-agent.md).
- **SDK:** `pip install vaani-sdk`, then `from vaani_sdk import VaaniClient`. Needs Python 3.9+. **MCP:** run with `npx -y vaani-research-mcp` (Node 18+, env `VAANI_API_KEY`). It is already registered in Claude Code for this project with these tools: `list_calls`, `get_call_details`, `get_call_transcript`, `trigger_call`, `start_webrtc_session`, `create_agent`, `update_agent_section`, `create_campaign`, `campaign_action`.
- **Pay-as-you-go limits:** 2 concurrent calls (add 5 lines for ₹2,000/month). Data retention is 30 days. Platform fee is ₹1/min. A phone number costs ₹600/month. Uptime SLA is 99.50%, support SLA is 3 days, and billing uses a prepaid wallet. Agents, knowledge bases and voices are unlimited. Bringing your own provider keys requires Enterprise. WebRTC calls carry no telephony charge.
- **Truths:** `success: true` from trigger-call means the call was dispatched, not answered. Results arrive asynchronously: the transcript returns 404 until ready, so wait for the `call_postprocessing` webhook. Latency (from the site): p50 full turn 600ms, p90 900–1200ms, interruption stop 100–200ms.
- **Path gotcha:** list and delete use plural `/api/agents`, config PATCH uses singular `/api/agent/{agent_id}/...`, create is `/api/create-agent`. A live check on 2026-10-31 got 404 for `/api/agents/{id}/persona`. `/api/trigger-call/` and `/api/campaigns/` take a trailing slash.

## Webhooks and events

| Feature | How | Key params / gotchas | Doc |
| - | - | - | - |
| Account call webhook | Dashboard **Settings → Webhooks** → add URL | No API endpoint registers webhooks. The URL must be public; use ngrok locally. Events are keyed by `room_name` (= call id) | [doc](vaani/guides/webhook-setup.md) |

| Post-call result | `call_postprocessing` | `call_duration` is in **milliseconds**. The payload is nested under `data`: `room_name`, `call_id`, `call_duration`, `end_reason`, `summary`, `entities`, `dispositions`, `recording_url`, `transcript` (`[HH:MM:SS] AGENT: ...`). ## Gaps: features named but not documented

- `POST /api/webrtc/token` ("Generate a LiveKit WebRTC token") is listed in the [API intro](vaani/api-reference/introduction.md) but has no page.
- There are no REST docs for: getting an agent's config, uploading a knowledge base, the tool/`actions` schema, registering webhooks, provisioning phone numbers, the SDK `sessions.*` endpoints, `health`, or rate limits (the SDK does define a 429 `RateLimitError`).
- openapi.json covers only 5 endpoints: trigger-call, call-history, transcript, stream and call_details. It has no agent or campaign endpoints.
- The webhook signing secret's source is undocumented, as is how to configure the warm-transfer target.
